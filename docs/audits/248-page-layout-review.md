## Criterio de revisión

La prioridad es que la persona encuentre **qué debe hacer ahora**, el contexto mínimo para decidir y la acción principal autorizada. Los datos de consulta profunda, configuración poco frecuente y auditoría pueden tener menor prominencia, siempre con un destino visible y conservando acceso.

- **Fuente comprobada:** orden JSX, componentes, condiciones de permisos, filtros, agrupaciones y límites CSS explícitos.
- **Hipótesis visual:** una altura o combinación puede desplazar contenido o crear vacío, pero necesita medición en navegador antes de llamarla defecto.
- **Propuesta de organización:** preferencia razonada, no un bug demostrado ni una funcionalidad ya entregada.
- **Conservar:** lo que ya reduce ruido o responde a un contrato; no reabrirlo sólo para producir cambios.

No se propone eliminar controles por una captura vacía, sumar monedas para compactar, convertir previsión en deuda, mover salarios a una vista sin permiso ni usar un único formulario para entidades con contratos diferentes.

## Cómo medir las propuestas sin inventar resultados

Para cada captura final, registrar ruta, rol sintético, viewport, tema, datos/estado y SHA. A 1440 px medir desde el final del header hasta el primer registro útil; a 390 px registrar cuántas filas ocupan encabezado/filtros y qué acción queda disponible. En tablas, distinguir scroll interno horizontal del desborde del documento. Los conteos no se comparan entre cuentas con permisos o datasets distintos.

Aceptar una mejora de espacio sólo si conserva: nombres y cantidades legibles, filtros aplicados visibles, acción primaria autorizada, targets táctiles/foco, mensajes de carga/vacío/error y datos ya cargados ante un fallo de actualización. Probar detalle→volver y modal→cancelar sin pérdida del borrador. La comparación de temas requiere capturas reales por tema; una lectura de CSS no acredita contraste visual.
